# Vinevault Core

## Run and verify

- Use Python 3.11 (the Docker runtime). From this repository, create/use a virtualenv and run `python -m pip install -r requirements.txt`.
- Copy `.env.example` to `.env` only if absent. Start local PostgreSQL with `docker compose -f docker-compose-test.yml up -d`, then run `python run.py` (reload enabled, port 8000). Despite its name, the test compose file only starts PostgreSQL; it runs no tests.
- For REST-only work without a broker, set `KAFKA_BOOTSTRAP_SERVERS=`. Both Kafka producer and consumer honor the empty value. Neither core compose file supplies Kafka.
- Containerized app: `docker compose -f docker-compose-prod.yml up --build`. Do not run both compose stacks together: they use the same database container name and host port 5432.
- Personal-context integration tests: set `TEST_DATABASE_URL` to an explicit `postgresql+asyncpg://` URL, then run `python -B -m unittest discover -s tests -p test_personal_context.py -v`. They create/drop unique temporary schemas, require schema-creation privileges, and bypass app lifespan/seeds. Without that variable they skip. No CI or lint/typecheck configuration is present.
- For focused API checks, inspect `/docs` or `/openapi.json`. `GET /api/v1/iam/health` is a basic service check, not proof of Kafka delivery. IAM login uses form fields `username` and `password`, not JSON.
- AI-only tests need no database/key: `python -B -m unittest discover -s tests -p test_inventory_intelligence.py -v`. All AI tests mock Google; never use a real key for automated verification.

## Startup and configuration traps

- **Use a disposable local database for startup checks.** `app/main.py` always seeds factory devices and reconciles edge credentials, with no environment guard: it deletes edge rows whose names are not in `EDGE_DEVICE_SEEDS`, restores the two seeded API keys, and reactivates those edges. Production mode does not disable this.
- Settings load `.env` in `app/core/config.py`. A nonempty `DATABASE_URL` overrides all `DATABASE_*` connection components, including the compose `DATABASE_HOST=db` override; leave it empty when using component settings.
- Database access is async SQLAlchemy/asyncpg. `postgresql://` URLs are converted automatically; URL query parameters are stripped by `app/core/database.py`. Enable TLS via `DATABASE_SSL=true`, not `?sslmode=require`.
- Before starting against an existing database, back it up, stop API instances and run `python -m alembic upgrade head`. The first revision backfills OWNER memberships and aborts on orphan legacy owners. Startup refuses old schemas; `create_all` cannot migrate columns. Downgrade is intentionally blocked; see `docs/space-tenancy.md`.
- `.env` is already tracked despite `.gitignore`. Do not expose or commit local credentials; keep regenerated bytecode ignored.

## Wiring and boundaries

- `app/main.py` owns router registration, ORM registration imports, seeds, and Kafka/outbox lifecycle; `app/dependencies.py` wires repositories, handlers, facades, and authentication.
- `device` also owns organizations, spaces, thresholds, commands, and alert incidents. `telemetry`, `wine_cellar`, and `inventory_intelligence` are separate contexts; cross-context facade contracts live in `interfaces/acl.py` with implementations in `applications/acl.py`. IAM uses its own flatter router/CRUD structure.
- All ORM contexts share `app.core.database.Base`; context-local `models/base.py` files re-export it. Ensure new ORM models are imported before `init_db()` so `create_all` sees them.
- Several device handler implementations live directly in `app/device/applications/command_handlers/__init__.py`; check there before assuming a class is missing or adding a duplicate.
- All space-creation routes, including `/api/v1/user/onboarding`, use `PersonalSpaceService`/`SpaceCreationUnitOfWork`: organization if needed, FREE/ACTIVE space, OWNER membership and default cellar commit together. Space/cellar repositories use `auto_commit=False`; do not reintroduce early commits. The UoW owns the request transaction, including guard reads. Creation adds `default_wine_cellar`; ordinary space reads do not.
- `authorize_space_request` guards user routers (spaces, cellars, devices, alerts, AI), including indirect IDs; do not add unguarded tenant routes. Membership is authoritative: legacy owner fields and IAM superuser status do not bypass roles. Edge routes retain separate API-key auth. Purpose, plan and role are per-space; see `docs/space-tenancy.md` for the matrix.
- Space deletion uses `SpaceDeletionService`/`SpaceDeletionUnitOfWork`: lock and authorize the space, reject assigned devices, then delete inventories, cellars and space in one transaction. Bulk cellar deletion is explicit to support existing FKs without cascade; never replace it with per-cellar repository calls that commit early.
- AI stock analysis keeps JSON by default; SSE is opt-in via Accept header or `stream=true`. Empty inventory always returns JSON before initializing Google. Keep the SQL snapshot bounded and never retry after text was emitted; see `docs/inventory-ai.md` for the wire contract and limits.
- Inventory uses physical `wine_inventory_items.name`; ORM/API retain `wine_name` as a legacy alias, not a second column. Advanced details, wine type and legacy age are nullable. Updates preserve omitted fields; explicit null clears optional values. Decimal JSON values are strings. See `docs/wine-inventory.md` before changing schemas/imports.
- Audited stock exits use `InventoryStockService`/`StockUnitOfWork`: lock the scoped item, subtract quantity and flush history before one commit. Never use a read/modify/write without locking or call an auto-committing repository inside that UoW. Movement history cascades on item deletion; absolute PUT/import counts do not create exit records.
- Quotas replace the legacy five-spaces-per-organization cap. Account slots count OWNER memberships; other roles do not consume them. Paid extras allow duplicate FREE purposes. Writers must lock account/space before counts and use space -> item lock order, including imports/stock exits. Never commit before validation; see `docs/resource-quotas.md` for formulas, error codes and context fields.

## Edge integration

- Read `edge-core-integration-spec.md` and `core-edge-topic-contract.md` before changing shared routes, payloads, or topics; update both sides of the Core/Edge contract. Some prose is stale: verify behavior against `app/device/infrastructure/kafka/device_event_publisher.py` and `device_event_consumer.py`.
- Edge callers to core use `Authorization: Bearer <edge_api_key>`, validated against active `EdgeDevice` rows, not a user JWT or local device headers (`X-Hardware-Id`/`X-API-Key`).
- Preserve provisioning topic `vinevault.provisioning.devices.changed` and required fields `device_id`, `hardware_id`, `api_key`, `status`.
- Kafka startup failures are logged and swallowed; a running REST service does not establish working event publication/consumption. Use a reachable broker and verify events when changing integration behavior.
